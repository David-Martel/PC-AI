# Streaming response deadlines

The two actual OpenAI-compatible SSE helpers now use one cancellation deadline through response headers and body reads. A header-first server can no longer leave a requested one-second timeout waiting three seconds for a partial line and then return success. `TimeoutSeconds`, endpoint/request fields, Unicode string output, host progress, DONE and existing EOF behavior remain unchanged. An optional `CancellationToken` lets a direct caller cancel either helper.

Only `Invoke-OpenAIChatStream` and `Invoke-OpenAICompletionStream` changed in `Modules/PC-AI.LLM/Private/LLM-Helpers.ps1`; the other 21 complete function AST extents remain byte-identical to predecessor `339B481CE815B3C3AF22011F056C8AB6CBE2E5051806CFCDA026FAA0551A0571`. Final helper SHA256 is `F2F72A98D1987C2461D2C97DFE87115774DD579A8C828BA2D1EA9BAD4D8203A1`.

## Cause and repair

`ResponseHeadersRead` completes before body content is consumed. [Microsoft documents that HttpClient.Timeout stops at that boundary](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpcompletionoption?view=net-10.0). The predecessor's synchronous `EndOfStream` / `ReadLine` operations had no body deadline. Its task `.Result` access also hid a header cancellation behind a subsequent null-valued method failure in the actual baseline.

A linked cancellation source begins before HTTP resource construction and receives the existing timeout. Its token is passed to `SendAsync`, `ReadAsStreamAsync` and `StreamReader.ReadLineAsync`; awaited results preserve their failure causes. The deadline is shared rather than renewed for each line. The reader's token overload is present in the [official .NET 7 source](https://github.com/dotnet/runtime/blob/v7.0.0/src/libraries/System.Private.CoreLib/src/System/IO/StreamReader.cs); this qualification used PowerShell 7.6.6 / .NET 10.0.12, not every historical PowerShell 7 runtime.

Each call attempts disposal of its own reader, stream, response, request, content, client and cancellation source. A first request/read failure remains primary. Cleanup ErrorRecords are attached as `PcaiStreamingCleanupFailures`; exact objects whose disposal failed are retained as `PcaiStreamingPendingResources` for caller custody. A cleanup-only failure also fails the call. Actual disposal failures and retry/interruption paths were not injected or qualified here. No new job, process or background PowerShell worker is introduced.

## Remaining gates

Malformed recognized SSE JSON/shape swallowing remains the predecessor behavior and requires a separate error/partial-output contract. Earlier runtimes, real providers, infinite/open SSE connections, interrupted host cleanup, disposal faults, network-stack cancellation faults, cross-machine deployment and consumer cancellation forwarding remain unqualified. Cancellation intentionally returns no successful partial string; already displayed host progress can still be visible. No global 85% coverage acceptance, coverage increment, performance improvement or general fault-custody guarantee is claimed. The observed inherited StrictMode failures need their own source ownership and genuine fixtures before repair.
