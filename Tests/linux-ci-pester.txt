# Pester files that run in the Linux self-hosted CI (.github/workflows/linux-ci.yml, job pester-lint).
#
# Why a list and not "every file tagged Portable": run on Linux 2026-10-20, 26 of the 57 files under Tests/Unit pass
# every Portable-tagged test when the whole directory is run file by file (322 tests), 21 fail (265 failing tests) and
# 10 have no Portable test. PC-AI.InferenceFallback.Tests.ps1 is one of the 26 but is left out: it fails 5 tests when
# it runs first in a fresh session, so it depends on module state that earlier files leave behind. The failing files
# exercise Windows-only surfaces (CIM/WMI, the registry, driver and network adapters, Hyper-V/WSL, a `C:` drive), so
# the Portable tag over-promises on a non-Windows host. Running the passing subset gives a gate that can fail for
# a real regression instead of one that is red from day one.
#
# Add a file here only after it passes on Linux in isolation:
#   pwsh -c "Invoke-Pester -Path Tests/Unit/<file> -Tag Portable"
# The workflow runs the listed files in ONE Invoke-Pester call, so a file must also pass when run before or after the others.
