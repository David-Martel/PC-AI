# Multiple USB4 edges to one enrolled host

Adding a second physical path is distinct from adding a second host. Peer UUID and an authenticated host key identify Milly, while namespace, boot, adapter instance/index and current XDomain locator identify each observed edge. A hub path or interface name can change and is not authorization. Link-local IPv6 probes require the current interface zone; an unbound ULA probe may follow another wired or wireless path.

The live MS01/Milly investigation found both XDomains reporting the same Milly UUID. A broad PCI-path naming rule named the new edge usb4-win and retained a former Windows transit IPv4 configuration. The existing bridge reconciler validated only its original enrolled edge. No second bridge attachment was made. A temporary IPv6-link-local-only NetworkManager profile on the otherwise addressless secondary Milly edge enabled strict pinned SSH, exact-source key authorization and an 8 MiB hash-verified transfer. Wrong-interface scope failed; original control connectivity and existing routes remained intact. This current-boot experiment does not establish persistent enrollment or automatic failover.

## Scoped stale-route repair

[Lifecycle route withdrawal](../Native/pcai_core/pcai_tb_cli/src/lifecycle.rs) previously skipped every stale record for a peer whenever another edge to that peer was Ready. That left stale alternate-edge host routes untouched. The repair preserves the current Ready edge while considering only the stale edge's explicitly scoped routes. Positive interface identity and ownership checks must hold before mutation; missing, contradictory or ambiguous bindings and external ownership are refusals, not permission to use an old name. Existing bridge and default/LAN protections remain in force. A proven authenticated replacement and transactional route journal remain necessary for broader automatic deployment; this patch is not that controller.

[Native contract CI](../.github/workflows/usb4-lifecycle.yml) runs actual Rust library and CLI tests on Windows and Linux and strict Clippy. The [review register](../Tests/Portable/usb4-multiedge-review.json) records reviewed source/test bindings. Recording runners assert exact mutation targets without changing host routes. They establish decision behavior, not physical disconnect or kernel convergence acceptance.

The existing V&V CLI test exposed a separate installed-host dependency: the local USB4 helper was invoked even when no matching extension topology existed. The [switch evidence producer](../Native/pcai_core/pcai_tb_cli/src/switch.rs) now skips that helper unless an enrolled extension topology requires it. An unrelated installed helper cannot supply a receipt for another topology. Scalar custody parsing and evaluation now explicitly refuse multi-extension certification: a good first edge cannot silently certify an absent second edge. Full per-edge receipt aggregation remains required. The V&V CLI assertions remain unchanged. A separate lifecycle CLI fixture now declares deliberately absent interfaces and requires explicit ownership refusals with no mutations, while retaining all original topology, firmware and transit assertions. A distinct empty-topology positive case requires success and no route actions. An invented foreign-host observation must not pass deployment readiness.

## Remaining controller contracts

- Enumerate enrolled root and named network namespaces, keyed by namespace inode and boot. Rebind changed names/indexes only after stable edge and authenticated host identity validation.
- Represent every observed edge, not only the first configured extension. Distinguish BUSY/UNKNOWN observation from an absent or failed link.
- Keep host management identity separate from per-edge addresses. Use authority/revision-bound ULA IPAM allocations, reject duplicate/overlapping/stale allocations, and retain scoped link-local discovery. Do not reuse the bridged LAN prefix as an independent point-to-point subnet.
- Bind probes to the candidate namespace and egress. Record actual socket endpoints and verify enrolled SSH keys or signed challenges; banners, NTLM hints and deterministic addresses alone cannot authorize Apply.
- Reconcile through plan, ownership/preimage checks, install replacement, readback, then exact stale-route withdrawal. Persist a custody journal and rollback only owned changes. Same-host parallel paths require explicit routing policy or loop-controlled L2 admission.
- Test add/remove/reconnect, namespace move, adapter rename/index reuse, host sleep, expired proof, missing permissions, route races and an unavailable preferred edge. Exercise real kernel convergence in a disposable topology before bounded live fault acceptance.

The existing [namespace design](design/usb4-sfp-namespace-vnv-design.md) and [CLI contract](../Native/pcai_core/pcai_tb_cli/README.md) describe broader context. Platform-wide procedure/traceability design remains in vigil-ai-tpm; engineering observations do not create accepted V&V credit.

The first hosted native-contract run exposed a V&V fixture that assumed USB4 hardware on the runner. Its corrected oracle checks raw provider observations, requires blocked/failing verdicts and nonzero exit when providers are missing or invalid, and preserves all five gate IDs, exact technical verdicts and acceptance-false status. The same compiled CLI test passes against the real provider and an empty provider view in a private mount namespace. No production validation was relaxed.
