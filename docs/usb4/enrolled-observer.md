# Enrolled USB4 networking

Build and test from the repository root:

```sh
cargo build --manifest-path Native/pcai_core/Cargo.toml -p pcai-tb --bin pcai-usb4-agent
cargo test --manifest-path Native/pcai_core/Cargo.toml -p pcai-tb
sudo /usr/local/libexec/pcai-usb4-agent observe /etc/pcai-usb4/policy.json
```

The [policy model](../../Native/pcai_core/pcai_tb_cli/src/edge_policy.rs) validates enrolled node/controller UUIDs and derives symmetric per-edge /64 addresses inside an approved locally assigned ULA /48. A full enrolled-pair collision check runs before inventory. Derived addresses are proposals, not installed addresses or fleet-wide IPAM reservations.

The [observer](../../Native/pcai_core/pcai_tb_cli/src/edge_observer.rs) reads root-namespace thunderbolt-net interfaces and actual sysfs controller ancestry. Interface names are presentation, not identity. Enrolled edges remain `ENROLLED_UNVERIFIED`: controller UUIDs are not cryptographic authentication. Explicitly protected or mastered interfaces are `PROTECTED`; unknown identities remain `UNKNOWN`. Missing inventory fails rather than producing an empty success. Listed namespaces are explicitly reported as uninspected; this implementation does not claim complete topology or namespace coverage.

The [CLI](../../Native/pcai_core/pcai_tb_cli/src/bin/pcai-usb4-agent.rs) supports observation, bounded qualification, profile rendering and explicitly adopted NM activation. Its policy must be a root-owned regular file without group/world write permission. Install the built binary at `/usr/local/libexec/pcai-usb4-agent`, policy at `/etc/pcai-usb4/policy.json` (root:root, mode600), and the [service](../../Deploy/usb4/pcai-usb4-observer.service) and [timer](../../Deploy/usb4/pcai-usb4-observer.timer) under `/etc/systemd/system/`. Verify units before enabling the timer. Read observations through `journalctl -u pcai-usb4-observer.service`. Stop/disable the timer to withdraw monitoring; no routes or profiles require rollback because observation never changes them.

The service drops all capabilities, restricts address families and makes the filesystem read-only. It intentionally has no SSH credentials or network-configuration authority. A timer refreshes observations after reconnect and resume without subscribing to a particular interface name. The optional udev enrollment rule also enqueues discovery and adopted NetworkManager activation; timers cover missed events.

## Verification boundaries and remaining integration

Policy tests protect deterministic reversed-endpoint allocation and reject unknown/local mismatches, unsafe runtime names, duplicate enrollment, invalid pools and actual subnet collisions. Observer fixtures protect actual sysfs ancestry, renamed interfaces, existing master ownership and unknown-peer nonpromotion; the missing-inventory selector protects provider failure semantics. Tests are adjacent to the implementation above. Current live receipts and independent reviews belong in the fleet evidence repository, not embedded deployment credentials.

The observation command does not change configuration. Adopted activation is separately described below; a successful observer run never implies networking readiness.

## Persistent deployment and qualified recovery

The [namespace collector](../../Native/pcai_core/pcai_tb_cli/src/namespace_inventory.rs) enters only approved namespaces through bounded subprocesses. It validates namespace inode before/after, child identity, policy epoch and hash. Privileged `observe-all` can cover the approved switch namespace; the capability-free observer service cannot enter it and must remain explicitly incomplete. Actual namespace inode, boot ID, timestamp and policy SHA travel in output. Consumers must apply freshness limits and retain failures rather than prior green status.

The [udev rule](../../Deploy/usb4/80-pcai-usb4-enrollment.rules) clears old enrollment properties before importing fresh ones for an enrolled unprotected interface. It performs no networking or SSH inside udev. `networkd-profile POLICY INTERFACE` renders an IPv6-only profile matched by enrolled edge property and driver. Review/install that profile under `/etc/systemd/network/`, import the property on only the intended interface, reload networkd and reconfigure that interface. Preserve and retire an obsolete competing Netplan source stanza; never edit generated `/run` files or globally restart networking. A newly enrolled controller pair still requires its own reviewed profile.

[Adopted NM activation](../../Native/pcai_core/pcai_tb_cli/src/nm_edge.rs) accepts exactly one policy-enrolled profile UUID with stable-id equal to the edge ID. It requires manual derived IPv6 /64, IPv4 disabled, autoconnect disabled, no defaults, routes, gateways, routing rules, controllers or secondary profiles. Fresh sysfs identity/index checks and foreign-owner refusal precede changes. Only the adopted interface binding and activation may change. Success is ACTIVE_UNVERIFIED, not authenticated; activation timeout is uncertainty because NetworkManager can finish an accepted request asynchronously. Ubuntu may persist its authoritative profile source under `/etc/netplan/90-NM-UUID.yaml` while the generated NM filename remains under `/run`. Verify the persistent source.

Install the [NM service](../../Deploy/usb4/pcai-usb4-nm.service) and [timer](../../Deploy/usb4/pcai-usb4-nm.timer) after preserving prior settings and enrolling the exact owned profile. Root D-Bus authorization permits the narrowly checked activation; the service has an empty capability set. Its autoconnect setting stays disabled so enrollment precedes activation. No bridge, default route, firewall or forwarding changes are implemented.

The [qualification probe](../../Native/pcai_core/pcai_tb_cli/src/edge_probe.rs) requires a direct source-qualified route and source-bound pinned SSH. It refuses gateway/via routes and validates peer node ID and actual SSH socket endpoints, then rechecks interface/namespace identity. Provision the public peer ID at `/etc/pcai-usb4/node-id` and extend the existing key restriction by the exact approved source only, over a previously trusted management path, preserving options and protected preimage. The trusted SSH alias supplies account, key and pinned known-host file. No key material belongs in policy/evidence. No reciprocal authentication is implied.

The [qualification service](../../Deploy/usb4/pcai-usb4-qualify.service) and [timer](../../Deploy/usb4/pcai-usb4-qualify.timer) use read-only user SSH configuration through runuser. Only SETUID/SETGID capabilities are retained, including ambient propagation needed by the tested oneshot child execution; there is no NET_ADMIN/SYS_ADMIN. Agent/proxy/local-command/forwarding/multiplex reuse are disabled. A process exit0 containing UNVERIFIED or REFUSED is not readiness.

MS01/Milly live evidence now covers persistent source readback, approved namespace inventory, pinned exact-source authentication and secondary-profile interruption/timer recovery. Profile interruption is distinct from physical unplug, sleep/resume and reboot. Remaining gates: least-privilege periodic namespace collection, full install/adopt rollback automation and failure injection, physical reconnect/resume, Windows runtime parity, global IPAM admission and monotonic epochs, external status consumption, and vigil-utils/vigil-spark/Ansible plus vigil-ai-tpm registration. Dashboard consumers need separate discovery, configuration, authenticated-link, scope/freshness and application-readiness states. PC-AI remains the code home; broader requirements and procedure/V&V authority remain vigil-ai-tpm.

### Device re-enumeration findings

The [networkd fallback](../../Native/pcai_core/pcai_tb_cli/src/networkd_edge.rs), [service](../../Deploy/usb4/pcai-usb4-networkd.service) and [timer](../../Deploy/usb4/pcai-usb4-networkd.timer) cover an observed early-udev discovery gap. Reconciliation requires one root-owned exact rendered profile, no effective profile/prefix/global drop-ins across networkd configuration directories, fresh controller/index identity, explicit NM-unmanaged custody, and no foreign networkd profile. It imports the enrollment property again and rechecks custody before reconfiguring only that edge. A changed/foreign profile refuses activation. The service has empty capabilities; `/sys/devices` is writable only to permit its bounded targeted uevent trigger, so it is a privileged configuration service rather than the capability-free observer's read-only sandbox.

`nm-unmanaged-profile POLICY INTERFACE` renders an administrative reservation for only the observed enrolled edge MAC. Install that reviewed reservation only on its networkd host. Never reserve all thunderbolt-net devices by driver: that would change unknown/protected custody. Transition an existing active NM owner explicitly; the agent will refuse to evict it. A changed MAC requires new reviewed reservation and is not automatically trusted.

Systemd services publish private atomic records under `/run/pcai-usb4-status/` using the [status writer](../../Native/pcai_core/pcai_tb_cli/src/status_record.rs). Directory ownership/mode, fixed operation names, exclusive staging, symlink refusal and file/directory sync precede publication. Records carry boot/policy/time identity. These local files provide a consumer contract, not a deployed dashboard API; consumers must reject stale or mismatched data. Network-operation errors remain UNVERIFIED because an accepted asynchronous request may still finish.

Live driver-unbind/rebind testing recovered a new interface index and owned profile but then exposed a separate carrier-up/zero-RX kernel datapath stall on both Milly wired paths. Wi-Fi remained usable. Paired Milly network-service rebinding restored traffic and pinned secondary SSH; no host reboot/controller reset was used. Thus profile interruption recovery is qualified, while unattended recovery after driver re-enumeration remains unqualified. Failed and retest receipts are retained in fleet evidence. Automatic resets are deliberately not implemented; kernel/tunnel diagnosis and controlled recovery remain open engineering work.
